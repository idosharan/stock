# אייג'נט ניתוח טכני — בורסת ת"א 📈

## התחלה קצרה: נייד ו-Google AI

פתחו את [האתר בחבילה](index.html). בנייד התיק מוצג כהחזקות עם שדות מסומנים,
הכפתורים מותאמים למגע והדוח נגלל כחלק מהעמוד. במחשב נשארת תצוגת הטבלה.
רשימת הדוחות מציגה רק קבצים שקיימים בחבילה; אין בכך הפקת דוח חדש.

**אין צורך לחבר חשבונות Google ו-GitHub בהתחברות משותפת.** החיבור הקיים הוא דרך
מפתח Gemini API: GitHub שולח את תקציר הדוח ל-Google ומקבל הסבר קצר בעברית.
הוא יכול לעזור להבין את מצב התיק, ההתראות והנתונים החסרים. הוא אינו משפר אוטומטית
את החיזוי, אינו משנה ציונים ואינו מבצע מסחר, סנכרון Drive או שליחה ל-Gmail.

### איך מפעילים

1. פתחו את [המאגר שלכם ב-GitHub](https://github.com/idosharan/stock).
   בחרו **Add file > Upload files** והעלו את **תוכן** החבילה, לא את התיקייה העוטפת.
   העדכונים לתצוגה נמצאים ב-[report-view.js](report-view.js), ב-[src/html.ts](src/html.ts)
   וב-[index.html](index.html). אל תדרסו תצורת תיק או היסטוריה חדשה שכבר קיימת בענן
   באמצעות עותק ישן מהחבילה. **לשדרוג אתר קיים** השתמשו ברשימת הקבצים בסעיף
   [סיכום התיק בראש ה-HTML](#סיכום-התיק-בראש-ה-html) והעלו גם את [report-view.js](report-view.js)
   ואת [tests/report-view.test.ts](tests/report-view.test.ts) אם עדכון הנייד הקודם עדיין לא הועלה.
   אל תחליפו את האינדקס בענן באינדקס של החבילה: הריצו `action=report` כמתואר בהמשך,
   כדי שייבנה מחדש מרשימת הדוחות שבענן. אם Pages מופעל, ההרצה המוצלחת תפרסם את העדכון.
2. ודאו שבמאגר קיים [.github/workflows/reports.yml](.github/workflows/reports.yml)
   בענף ברירת המחדל. קובץ בשם זה בשורש לא מספיק. אם זה מאגר חדש, הפעילו את Actions
   ובדקו ב-**Settings > Actions > General > Workflow permissions** שיש הרשאת כתיבה
   לשמירת דוחות, בהתאם למדיניות המאגר.
3. היכנסו עם חשבון Google ל-[Google AI Studio](https://aistudio.google.com/api-keys)
   וצרו מפתח API בפרויקט שלכם. **מנוי Google AI אינו מבטיח מכסת API או חיוב כלול.**
   בדקו [חיוב ומכסות](https://ai.google.dev/gemini-api/docs/billing) ואת
   [תנאי השימוש בנתונים](https://ai.google.dev/gemini-api/terms) לפני הפעלה.
4. ב-GitHub פתחו **Settings > Secrets and variables > Actions > Secrets > New repository secret**.
   כתבו בשם `GEMINI_API_KEY` והדביקו את המפתח בערך, **רק במסך זה**. לא בקוד, באתר או בשיחה.
5. עברו ללשונית **Variables > New repository variable** והוסיפו את שני המשתנים:

   | שם | ערך |
   | --- | --- |
   | `GEMINI_MODEL` | מזהה מודל שזמין לפרויקט ב-AI Studio ותומך ב-`generateContent`, ללא הקידומת `models/`. |
   | `SEND_REPORT_TO_GEMINI` | `true`, רק לאחר שבדקתם את תנאי הנתונים והעלויות והסכמתם לשליחת התקציר. |

6. פתחו **Actions > Manage & Build Reports > Run workflow**.
   בחרו את ענף ברירת המחדל, `action=report` ו-`mode=daily`, ולחצו **Run workflow**.
   במאגר חדש כדאי להריץ קודם `action=list` ולוודא שהתיק נכון.
7. בסיום פתחו את ההרצה ואת **Summary**: שם יוצגו התקציר ופרשנות ה-AI, אם הצליחה.
   אפשר גם להוריד את חבילת **Artifacts** של אותה הרצה; בתיקיית `reports` נמצא הקובץ
   `latest-daily-ai.txt` (או `latest-weekly-ai.txt` לשבועי). הפרשנות נשמרת גם בראש
   דוח ה-HTML שנוצר באותה הרצה, בסעיף **התיק שלי · סיכום החלטות**. אין בחבילה חלון צ'אט.
8. אם לא התקבלה פרשנות, חפשו ב-**Summary** את השורה `Gemini diagnostic:` והיעזרו בטבלה הבאה.
   הדוח הרגיל ממשיך לעבוד גם בכשל AI. לכיבוי שנו `SEND_REPORT_TO_GEMINI` ל-`false`.

### סיכום התיק בראש ה-HTML

בראש דוחות חדשים, מיד אחרי הכותרת, מופיעים **השורה התחתונה**, מצב ההחזקות
(מחיר, רווח/הפסד, ציון ושינוי, סטופ), ושלוש קבוצות: **קנייה / חיזוק**, **מכירה / צמצום**,
**החזקה / מעקב**. בנייד השדות מסומנים והקבוצות נערמות לקריאה ללא גלילה לצדדים.
הסיווג מבוסס על כללי הדוח; Gemini מתבקש להוסיף ארבע פסקאות קצרות בעברית.
החזקות ללא כיסוי טכני אינן מקבלות המלצת החזקה. אין חישוב תשואה כוללת ללא כמויות.

**הקבצים לעדכון זה, בתיקיות המתאימות בענף ברירת המחדל:**

- [src/ai-report.ts](src/ai-report.ts) ו-[src/brief.ts](src/brief.ts) (קבצים חדשים).
- [src/html.ts](src/html.ts), [src/summary.ts](src/summary.ts), [src/report.ts](src/report.ts).
- [tools/automation.ts](tools/automation.ts).
- [tests/automation.test.ts](tests/automation.test.ts), [tests/report.test.ts](tests/report.test.ts), [tests/summary.test.ts](tests/summary.test.ts).
- המדריך הזה. אין צורך להעלות את תיקיית `docs`, קבצי תצוגת הבדיקה או `.cache`.

אל תחליפו את `data`, `reports`, `index.html` או היסטוריית התיק בענן בעותקים מקומיים.
לאחר ההעלאה הפעילו **Run workflow חדש**, `action=report`, `mode=daily`.
כאשר Gemini מצליח והקישור לדוח אומת, תופיע ב-Summary השורה
`AI summary embedded at the top of the generated HTML report`.
פתחו את הדוח החדש באתר לאחר פרסום Pages, או את קובץ ה-HTML מתוך Artifacts.
דוח שכבר הורד או פורסם בעבר אינו משתנה בדיעבד.

אם Gemini נכשל או כבוי, נתוני התיק וקבוצות הפעולה נשארים בראש ה-HTML עם ציון שהפרשנות
אינה זמינה. אין שימוש בפרשנות ישנה. אם מופיע `HTML embedding was skipped`, ודאו
שכל קובצי העדכון הועלו יחד והתחילו הרצה חדשה. תיעוד פנימי וחתימות של הדוח והתקציר
מונעים שילוב פרשנות בדוח אחר; המפתח אינו נכלל ב-HTML ואין קריאה ל-Google מהדפדפן.

### אבחון Gemini בהרצה הבאה

**לעדכון האבחון באתר קיים:** השתמשו ברשימת הקבצים של סיכום ה-HTML לעיל,
כולל [tools/automation.ts](tools/automation.ts) ו-[tests/automation.test.ts](tests/automation.test.ts).
אין להחליף דוחות, היסטוריה, אינדקס או תצורת תיק. לאחר שמירת העדכון בענף ברירת המחדל,
התחילו **Run workflow חדש** עם `action=report` ו-`mode=daily`; הרצה ישנה אינה מתעדכנת בדיעבד.

| קוד ב-Summary | משמעות ומה לבדוק |
| --- | --- |
| `disabled` | המשתנה `SEND_REPORT_TO_GEMINI` אינו בדיוק `true`. |
| `missing_key` | ה-Secret בשם `GEMINI_API_KEY` חסר או ריק בשלב ההרצה. בדקו את שמו ואת מיפויו ב-workflow. |
| `missing_model` / `invalid_model` | בדקו את `GEMINI_MODEL`, ללא `models/`, מרכאות או רווחים. |
| `http_400` | Google דחתה את הבקשה. בדקו התאמה למודל ול-API, פרמטרים והגדרת מפתח; הקוד לבדו אינו מזהה סיבה יחידה. |
| `http_401` / `http_403` | האימות או הגישה נדחו. בדקו מפתח, מגבלות מפתח והרשאות פרויקט. |
| `http_404` | המשאב לא נמצא. בדקו מזהה מודל וזמינותו דרך `generateContent` בפרויקט. |
| `http_429` | מגבלת קצב או מכסה. בדקו שימוש, מכסה וחיוב ב-Gemini API, בנפרד ממנוי Google AI. |
| `timeout` / `http_408` | הבקשה בוטלה או חרגה מזמן ההמתנה. מגבלת הלקוח היא 60 שניות לכל ניסיונות Gemini, ההשהיות וקריאת התשובה יחד, לכל דוח. |
| `max_tokens` | Google דיווחה `MAX_TOKENS`: התשובה לא הושלמה במגבלת 1,600 הטוקנים הקיימת ולכן לא פורסמה. |
| `blocked` | Google דיווחה על חסימת הבקשה או הפלט. |
| `network_error` / `insecure_tls` | בדקו חיבור ותעודות TLS מהימנות; אין לבטל אימות תעודות. |
| `http_5xx` | שגיאת שרת בבקשת Gemini. בשגיאה חוזרת בדקו את `HTTP status:` שבאותה שורה, במקום להריץ שוב ושוב. |

בשגיאת HTTP מופיע כעת גם המספר המדויק, לדוגמה `Gemini diagnostic: http_5xx. HTTP status: 503.`
`500` מציין שגיאה פנימית, `502` שגיאת שער, `503` שירות לא זמין ו-`504` חריגה מזמן המתנה בשער.
המספר מסייע למקד את הבדיקה, אך אינו מוכיח תקלה כללית בשירות או שהמפתח והמודל תקינים.

בעקבות שגיאת `503` חוזרת נוספו עד שני ניסיונות חוזרים לבקשת Gemini בלבד, לאחר השהיות
של כ-2 וכ-4 שניות עם תוספת אקראית קטנה. אם Google שולחת `Retry-After`, הקוד מכבד
את ההשהיה המבוקשת; אם היא ארוכה מדקה לא נשלחת בקשה נוספת. כל הניסיונות חולקים
מגבלת זמן אחת של 60 שניות. שגיאה אחרת, timeout או תשובה לא תקינה אינם מפעילים ניסיון חוזר.
התקציר עשוי להישלח עד שלוש פעמים לכל דוח, דבר שעשוי להגדיל שימוש ועלויות API;
הניסיונות חוזרים על אותה בקשה ללא שינוי במודל או בתקציב הטוקנים. איסוף נתוני השוק אינו רץ מחדש לצורך הניסיונות.
אם גם לאחר מכן מתקבל `503`, ה-AI נשאר לא זמין והדוח הרגיל ממשיך כרגיל. אין טעם להריץ
דוחות ללא הפסקה: בדקו את [מצב השירות](https://aistudio.google.com/status) ופנו לתמיכת Google
עם הקוד והשעה. אין לשלוח מפתח או את פרטי התיק.

קודים אחרים מלווים בהסבר קבוע באנגלית על מבנה תשובה, מגבלת גודל או בדיקת בטיחות.
האבחון אינו מדפיס מפתח, תוכן תיק, תגובת ספק גולמית או הודעת חריגה. התקציר הרגיל עדיין
מוצג ב-Summary כרגיל ועשוי להכיל מידע אישי: לצורך עזרה שתפו **רק את שורת האבחון**.
לאחר אבחון `timeout` הורחבה מגבלת ההמתנה מ-20 ל-60 שניות; כעת היא משותפת גם לניסיונות החוזרים.
המודל, ה-API ומגבלת 1,600 הטוקנים נשארו ללא שינוי. אם הדקה מסתיימת ללא תשובה מלאה,
הדוח הרגיל נשמר והפרשנות אינה מתפרסמת. ההרחבה אינה מבטיחה הצלחה בענן ואינה מוכיחה שהמפתח תקין.
להפעלת העדכון העלו שוב את [tools/automation.ts](tools/automation.ts) ואת
[tests/automation.test.ts](tests/automation.test.ts), והתחילו הרצה חדשה כמתואר למעלה.

### השלב נשאר פעיל אחרי יצירת הדוח

אם `Run analysis in fresh processes` ממשיך לרוץ אחרי `הדוח נוצר בהצלחה` ואחרי רשימת
`5 המובילות`, חישוב הדוח הסתיים אך תהליך Node עדיין לא יצא. שלב Gemini עוד לא התחיל.
תוקן מסלול שבו תגובות HTTP שלא נצרכו, למשל שגיאות מ-Investing, השאירו חיבורים פעילים.
הקוד סוגר כעת תגובות שנזרקות בבדיקת הקישוריות, באימות Yahoo ובמסלולי שגיאה של ספקי המחירים.

1. העלו את [src/data.ts](src/data.ts) ואת [tests/data.test.ts](tests/data.test.ts)
   לתיקיות המתאימות במאגר, ושמרו את העדכון בענף ברירת המחדל. אין להחליף דוחות או תצורת תיק.
2. אם ההרצה הישנה עדיין תקועה, שמרו את הלוג ולחצו **Cancel workflow**.
   דוח שנכתב במחשב ההרצה אינו בהכרח נשמר במאגר או פורסם לפני הביטול.
3. התחילו **Run workflow חדש** עם `action=report` ו-`mode=daily` ובדקו שהשלב מסתיים
   ושההרצה עוברת ל-**Fresh deterministic digests and optional AI narrative**.

התיקון נבדק מול שרת מקומי המשאיר תגובות שגיאה פתוחות, כולל יציאה טבעית של תהליך נפרד,
אך עדיין דורש אימות בהרצה בענן. הוא אינו עוקף חסימות של ספקים ואינו משלים מחירי קרנות חסרים.

**פרטיות:** התקציר שנשלח כולל החזקות ומידע כספי אישי. אין להפעיל את החיבור במסלול
שתנאיו אוסרים מידע רגיש; בשירותים חינמיים התוכן עשוי לשמש לשיפור מוצרים ולהיבדק בידי אדם.
בדקו את תנאי הפרויקט בפועל. מפתח ב-Secrets אינו הופך את התיק או את האתר לפרטיים.
אתר GitHub Pages בדרך כלל ציבורי; אל תפעילו פרסום בלי החלטה מודעת על חשיפת הדוחות.

**בטלפון:** לאחר פרסום האתר פתחו את [כתובת האתר המיועדת](https://idosharan.github.io/stock/)
ב-Chrome ב-Android ובחרו **הוספה למסך הבית / התקנת אפליקציה**. אם Pages עדיין לא הוגדר,
ראו [הוראות הפרסום האופציונלי](#pages-אופציונלי). ההתקנה אינה נדרשת לחיבור Gemini.

**בלי API:** אפשר לפתוח את התקציר הרגיל ב-Gemini בחשבון שלכם ולבקש:
"סכם בעברית את ההתראות, הנתונים החסרים והסיכונים. אל תמציא מחירים או הבטחות תשואה."
בדקו את תנאי הפרטיות והשמיטו מידע אישי לפני העלאה ידנית. זה אינו חיבור אוטומטי.

אייג'נט אוטומטי ב-Node.js/TypeScript שמבקש נתוני מניות מהאינטרנט בכל הרצה,
מבצע ניתוח טכני (רצועות בולינגר, נרות יפניים, RSI, MACD, ממוצעים נעים),
סורק כתבות בעיתונות הכלכלית הישראלית ומפיק **דוח המלצות יומי/שבועי** של מניות לרכישה.

אפשר לנהל תיק ורשימת מעקב בטופסי GitHub Actions, ללא שרת יישום קבוע וללא מחשב דולק.
הדוחות הם HTML סטטי; GitHub מאמת את המשתמש ומריץ את העבודה בענן. אין צורך בחשבון Google
לליבת האוטומציה. הנתונים עשויים להיות חלקיים, מושהים או מהמסחר הקודם: בדקו את תאריכי הנתונים בדוח.

## מה הוא עושה

- 📊 מושך היסטוריית מסחר (OHLCV) מ-Yahoo Finance עבור מניות ת"א (סיומת `.TA`).
- 🧮 מחשב אינדיקטורים טכניים מרכזיים:
  - **רצועות בולינגר** (Bollinger Bands) + מדד %B
  - **נרות יפניים**: פטיש, כוכב נופל, דוג'י, בליעה שורית/דובית, כוכב בוקר/ערב, שלושה חיילים לבנים / שלושה עורבים שחורים
   - **RSI**, **MACD**, ממוצעים נעים (SMA 5/13, וניתוח ארוך טווח)
  - **סטוכסטי**, **Williams %R**, **ADX**, **ATR**, **OBV**
  - **CCI** (Commodity Channel Index), **MFI** (Money Flow Index), **ROC** (מומנטום), **VWAP** מתגלגל

## חיזוי היסטורי ואימות

המנוע ב-[src/forecast.ts](src/forecast.ts) משווה את המניה למצבי עבר דומים לפי מומנטום,
תנודתיות, מרחק מממוצע ומשיא, נפח וחוזק יחסי מול מדד מתואם לפי תאריך.
המקרים מסוננים לפי מגמה, דשדוש או לחץ. אלה כללים קבועים מראש, לא משקולות שאומנו על תקופת הבדיקה.

- אופקים: 5, 10 ו-20 ימי מסחר; כניסה בפתיחת המסחר הבאה ויציאה בסגירת יום האופק.
- עלות ברירת מחדל: 20 נקודות בסיס לעסקה מלאה, כולל הנחת עמלות והחלקה. אין סימולציית סטופ או תיק השקעות.
- לפחות 12 מקרים לא חופפים בכל אופק, עד 40 שכנים דומים; אחרת אין אומדן הסתברות.
- שכיחות עלייה עם רווח סמך Wilson של 95%, חציון נטו, P10/P90 וקו בסיס בלתי מותנה.
- רווח הסמך הוא בקירוב: תלות בין תקופות מקטינה את המדגם האפקטיבי. P10/P90 מתארים פיזור עבר, לא תחום מובטח לעתיד.
- החיזוי ההיסטורי משתמש רק בימים שהסתיימו ב-UTC. גם לאחר סגירת הבורסה המקומית נר היום ייכלל רק ביום UTC הבא. הניתוח הטכני הרגיל עשוי להיות תוך-יומי.
- נתוני הספק אינם מאגר point-in-time מלא של כל המניות שנמחקו, ואין כאן סדרת תשואה כוללת מאומתת לפעולות הון ודיבידנדים.


בדיקת התחזיות כרונולוגית, עם תוצאות עבר שהושלמו לפני תאריך ההערכה וללא חפיפה בתוך כל מניה ואופק.
הדוח מציג כיסוי, Brier מול קו בסיס (נמוך עדיף), קבוצות שכיחות צפויה מול בפועל ותשואות נטו.
תצפיות בין מניות עשויות להיות מתואמות. המדגם הוא המניות הראשונות ברשימת המעקב הנוכחית.

## תיק ורשימת מעקב

מקור המכשירים המחייב הוא [data/instruments.json](data/instruments.json), לא רשימות ידניות בקוד.
הממשק הנתמך הוא הטופס המתואר בהמשך; מקומית ניתן להציג את המצב באמצעות `npm run instruments -- --list`.
מקורות חדשות ופרמטרי ניתוח נשארים ב-[src/config.ts](src/config.ts), ואינם שדות בטופס.
לבדיקות או להרצות מקומיות מבודדות אפשר לבחור קובץ חלופי באמצעות `INSTRUMENT_CONFIG_PATH`;
זהו נתיב מסביבה מהימנה בלבד, לא קלט מטופס הניהול. הקובץ עדיין חייב לעבור את כל בדיקות התקינות.
נתיב מפורש שנמסר לטוען גובר על משתנה הסביבה; כשאין נתיב חלופי נטען קובץ ברירת המחדל שלעיל.

נתמכות מניות ת"א בעלות סימול Yahoo מאומת עם `.TA` ומניות/ETF אמריקאיים בדולר עם נתוני Yahoo.
בתיק וברשימת המעקב הוולידטור מאפשר תחביר אמריקאי פשוט: אות לטינית גדולה ואחריה עד 14 אותיות
גדולות, ספרות או מקפים (`HPQ`, `BRK-B`); או סימול ת"א המסתיים ב-`.TA`.
סמלים מבורסות אחרות כמו `VOD.L`, סימולי מדדים שמתחילים ב-`^`, מט"ח עם `=` וסיומות אחרות נדחים.
זהו סינון תחבירי בלבד: הוא אינו מוכיח בורסה, סוג נכס או מטבע ציטוט. עדיין נדרש אימות מול
המטא-נתונים של המקור; אין כאן אימות מטא-נתונים אוטומטי. המגבלה מצמצמת אי-התאמות ידועות ליחידות המנוע.
קרנות סל ת"א ללא היסטוריית Yahoo נתמכות כהחזקות **מחיר בלבד**: מספר נייר בן 5-10 ספרות
וקישור Investing מאומת, ללא המצאת סימול חלופי. ייתכנו מחיר ותשואה מול הכניסה, אך אין הבטחה
לציון טכני, סטופ רצף, חיזוי או כיסוי מלא של התראות יציאה. `trigger_index` עוקב אחרי מדד ייחוס,
לא אחרי היסטוריית הקרן, ואינו מבטיח התאמה למוצר ממונף. אין תמיכה כללית מובטחת באופציות,
חוזים, אג"ח, קרנות ללא מקור נתונים או המרת מטבעות; תחביר סימול תקין אינו אישור לזמינות נתונים.
הגבולות הם 500 רשומות מעקב ו-200 החזקות, לא התחייבות שכל הכמות תיאסף בזמן הריצה.

`trigger_index` מוגבל למדדי `WORLD_INDICES` שנאספים עבור ניתוח המדדים:
`^GSPC`, `^DJI`, `^IXIC`, `^NDX`, `^RUT`, `^VIX`, `TA35.TA`, `TA90.TA`, `207.TA`,
`^GDAXI`, `^FTSE`, `^FCHI`, `^STOXX50E`, `^N225`, `^HSI`, `000001.SS`, `^KS11`.
`TA125.TA` משמש בנפרד כ-benchmark, אך אינו טריגר נתמך ויידחה עם רשימת המדדים המותרים.
גם במדד נתמך ייתכנו נתונים חסרים. רשימת `SUPPORTED_TRIGGER_INDICES` ב-[src/instruments.ts](src/instruments.ts)
נבדקת מול `WORLD_INDICES` כדי למנוע סטייה ביניהן.

מחירי כניסה והתראה חייבים להיות חיוביים, עם נקודה עשרונית וללא פסיקים או סימני מטבע:
**ת"א באגורות, לא בשקלים; נכסים אמריקאיים ב-USD בלבד**. למשל `4502` אגורות = 45.02 ש"ח ליחידה.
ההחזקה הקיימת `1145903` נשארת עם כניסה `4502` וקישור
`https://www.investing.com/etfs/ksm-4d-sp-energy`; אין להוסיף אותה שוב ואין להחליפה בסימול משוער.
כל יתר ההחזקות נשמרות; פעולת הסרה בטופס היא מחיקת רשומה בלבד, לא הוראת מסחר.

נבדקים **עד 100 קבצים ועד 25 MiB לקובץ** לפני ההעתקה וגם גודל התוצאה לאחריה.
העתקות רגילות מאומתות ב-SHA-256, ומסד ההיסטוריה מיוצא כתמונת SQLite עקבית עם בדיקת תקינות וקריאה חוזרת.
לפי מבנה הפרויקט ב-7.9.2026: 20 מקור + 10 בדיקות + 6 כלים + workflow אחד + 7 שורש + 6 נכסי לקוח + קובץ נתונים אחד +
מסד אחד + 30 דוחות = 82; עם שני תקצירים 84, ועם ארבעה **86 קבצים**. תוספת קוד עתידית צורכת מהמרווח,
והמערכת בודקת בפועל שהתוצאה נשארת לכל היותר 100 קבצים.
שמירת 30 דוחות מגבילה את מספרם, לא את גודל מסד הארכיון: אם SQLite גדל מעל 25 MiB ההכנה תיעצר;
אין למחוק היסטוריה כדי לעקוף את הבדיקה, ונדרשת החלטת אחסון/מסירה נפרדת.

1. צרו מאגר GitHub, רצוי **Private**. בחרו **Add file > Upload files** וגררו את **תוכן** תיקיית הייצוא, לא את התיקייה העוטפת. ניתן לגרור תיקיות כדי לשמר היררכיה; בחירת קבצים בודדים אינה תחליף לשימור נתיביהם.
2. הציגו קבצים מוסתרים בסייר. בוררי קבצים/גרירה עשויים להשמיט שמות שמתחילים בנקודה: בדקו במפורש את `.github/workflows/reports.yml`, `.gitignore` ו-`.gitattributes` לפני סיום ההעלאה. אל תעלו ZIP בציפייה ש-GitHub יחלץ אותו.
3. אם `.github` לא נקלטה, השתמשו ב-**Add file > Create new file** עם השם המלא `.github/workflows/reports.yml` ותוכן הקובץ המקורי; כך נוצרת ההיררכיה. העלו/צרו גם את שני קובצי הנקודה בשורש. העלאת `reports.yml` לשורש לא מפעילה Actions.
4. ודאו ש-[package.json](package.json) ו-[data/instruments.json](data/instruments.json) בנתיבים המדויקים ושכל התיקיות נשמרו. השלימו את השינוי בענף ברירת המחדל, דרך PR אם נדרש. דפדפן אינו מחיל כללי `.gitattributes`; אין להסתמך עליו להמרת סיומות שורה. [מגבלות ההעלאה הרשמיות](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

### התקנה מהאתר

לאחר העלאת החבילה למאגר [https://github.com/idosharan/stock](https://github.com/idosharan/stock) והפעלת Pages,
כתובת ההתקנה המיועדת היא `https://idosharan.github.io/stock/`.

1. פתחו את הכתובת ב-Chrome ב-Android.
2. בחרו בתפריט הדפדפן **הוספה למסך הבית** או **Install app**. בתוך האתר יש מדריך הפעלה מובנה.
3. האפליקציה נפתחת בחלון עצמאי. היא עובדת במצב רשת בלבד: אין שמירת דוחות לאופליין ואין הבטחת נתונים בזמן אמת.
4. התצוגה הקומפקטית היא ברירת המחדל ושומרת על תקציר, התראות ותיק. לפתיחת כל הסעיפים או להדפסה מלאה השתמשו בפקדי ההרחבה/הדפסה בתוך האתר.
5. אימות GitHub נדרש רק לפעולות הניהול וה-CRUD דרך Actions. אין כאן מסחר, הוראות קנייה/מכירה או טופס ציבורי לנתונים פרטיים.

### הפעלת Actions

1. ב-**Settings > Actions > General** אפשרו את פעולות ה-workflow בהתאם למדיניות המאגר/הארגון. ב-**Workflow permissions** אפשרו הרשאות קריאה וכתיבה כשנדרש; עבודת הבנייה מבקשת `contents: write` כדי לשמור תצורה והיסטוריה.
2. בדקו הגנת ענף ו-rulesets. דרישת PR או חסימת כתיבה לבוט עשויות לדרוש הגדרה מתאימה מצד מנהל המאגר; `contents: write` אינו עוקף הגנת ענף. אין במערכת מסלול אוטומטי חלופי של PR.
3. ודאו שה-workflow נמצא בענף ברירת המחדל. פתחו **Actions > Manage & Build Reports > Run workflow**, בחרו את ענף ברירת המחדל ואת הפעולה. בקשות מענף אחר נדחות; גם התזמון משתמש בענף ברירת המחדל.
4. הריצו תחילה `action=list` לבדיקת התצורה, ואחריו `action=report`, `mode=daily`. בדקו את סטטוס השלבים והתוצר, לא רק את קיום דוח ישן. הבנייה מתקינה תלויות ומריצה בדיקות ובדיקות טיפוסים לפני שינויים.

ה-bot מבצע commits ו-push של שינוי התיק **לפני** פנייה לספקי נתונים, ובהמשך של דוחות והיסטוריה.
אלה פעולות מכוונות של הצינור בענן; כשל איסוף אינו מבטל עריכה שנשמרה. לא מתבצע rebase אוטומטי של SQLite
במקרה התנגשות. העבודות מסודרות באותה קבוצת concurrency, אך אין הבטחה שכל בקשה ממתינה תישמר בתור;
המתינו לסיום לפני שליחת שינוי נוסף ובדקו את היסטוריית הריצות. אין לשלוח שוב `add` שכבר נשמר.
אפשר להגדיר ב-**Settings > Secrets and variables > Actions > Variables** את `PORTFOLIO_CAPITAL`
(ברירת מחדל 100,000 ש"ח) לחישובי גודל פוזיציה; אין כאן ניהול כמויות תיק או המרת מטבע אוטומטית.

### עשרת שדות הטופס

| שדה | ערך ומשמעות |
| --- | --- |
| `action` | `report` הפקה, `list` הצגת כל התצורה, `add` הוספה, `update` עדכון, `remove` הסרה. |
| `mode` | `daily`, `weekly`, `both` עבור `report`. שינוי תיק מפיק תמיד יומי; ב-`list` אין הפקה. |
| `target` | `portfolio` להחזקות או `watchlist` למעקב. `list` מציג את התצורה כולה. |
| `identifier` | סימול Yahoo מאומת, כגון `DSCT.TA` או `HPQ`; מספר ת"א בן 5-10 ספרות רק להחזקת מחיר בלבד. החזקת Yahoo מנוהלת לפי הסימול גם אם ידוע מספר הנייר. |
| `name` | שם חובה ב-`add`; ריק ב-`update` שומר את השם. לא ניתן לנקותו עם `-`. |
| `entry_price` | חובה בהוספה ל-`portfolio`; חיובי באגורות לת"א או USD לארה"ב. ריק בעדכון שומר, `-` אסור. לא שייך למעקב. |
| `sector` | ענף אופציונלי בתיק או במעקב; ריק בעדכון שומר, `-` מנקה. |
| `investing_url` | בתיק בלבד: `https://www.investing.com/etfs/...` או `/equities/...`, ללא query, fragment או פרטי כניסה. חובה למספר ת"א ללא סימול; `-` מנקה רק כשהשדה אינו נדרש. |
| `alert_below` | בתיק בלבד: מחיר התראה חיובי באותן יחידות כמו הכניסה; ריק שומר, `-` מנקה בעדכון. |
| `trigger_index` | בתיק בלבד: מדד מהרשימה הנתמכת לעיל, כגון `^NDX` או `TA35.TA`; ריק שומר, `-` מנקה בעדכון. |

ב-`update` שדה ריק פירושו **ללא שינוי**; `-` מנקה שדה אופציונלי בלבד, ורק אם התצורה נשארת תקינה.
ב-`add` נדרשים מזהה ושם, ובתיק גם מחיר כניסה; `add` אינו upsert ודוחה רשומה קיימת.
`update` ו-`remove` דורשים רשומה קיימת. ב-`remove` ממלאים רק יעד ומזהה בנוסף לבחירות הטופס,
ומשאירים את ששת שדות התוכן ריקים. ב-`report`/`list` השדות האחרים אינם משנים מכשירים.
החזקת Yahoo מצטרפת למעקב; אי אפשר להסיר מהמעקב נייר שעדיין מוחזק. הסרה מהתיק אינה מסירה מהמעקב.
שדות לא מוכרים ושמות כפולים בתוך רשימת המעקב או בתוך התיק נדחים. שינוי שם בתיק או במעקב
מסנכרן את השם ברשומה התואמת לפי הסימול, בלי לשנות מחירי כניסה. ניקוי סקטור נשאר באחריות טופס הניהול.

דוגמאות: להפקה `action=report, mode=both`; להצגה `action=list`; להוספת מניה חדשה למעקב
`action=add, target=watchlist` עם סימול מאומת ושם; לעדכון הכניסה הקיימת
`action=update, target=portfolio, identifier=1145903, entry_price=4502` וכל יתר שדות התוכן ריקים.
להסרת רשומה בוחרים `remove` ואת מזהה הרשומה המדויק, לאחר בדיקת `list`.

### תזמון, תוצרים ותקלות

- היומי: `37 21 * * 1-5`, שני עד שישי ב-21:37 UTC. השבועי: `47 21 * * 5`, שישי ב-21:47 UTC. אלה שעות אחרי סגירת ארה"ב הרגילה, גם בשעון חורף; ההמרה לשעון ישראל משתנה עם שעון קיץ/חורף. אין לוח חגים של הבורסות ואין הבטחת נתוני סגירה עדכניים.
- GitHub עשוי לעכב ריצות מתוזמנות; במאגר ציבורי התזמון עשוי להיות מושבת אחרי 60 יום ללא פעילות. בדקו שה-workflow פעיל והפעילו מחדש ב-Actions בעת הצורך. גם הפקה מוצלחת יכולה להכיל נתונים ישנים או חלקיים.
- בדף הריצה ב-Actions מופיעים סטטוס ותקצירים דטרמיניסטיים. הורידו את artifact בשם `reports-<run_id>-<attempt>` (שמירה ל-30 יום בכפוף למדיניות החשבון). בתוך החבילה: `reports/latest-daily.txt`/`reports/latest-weekly.txt`, HTML ו-`run-status.txt`; תוספות AI נפרדות, אם נוצרו. התוצאה אינה תלויה ב-Pages או ב-Gemini.
- חלצו את כל החבילה ופתחו את [index.html](index.html), עם תיקיית `reports` לצדו ובלי לשטח את ההיררכיה. הורדת האינדקס בלבד אינה מספיקה לצופה. אפשר לפתוח גם דוח HTML יחיד ישירות; בדוחות חדשים התקציר מוטמע בו.
- `list` מציג JSON בדף הריצה ובלוג, אינו מפיק מחדש דוחות ואינו יוצר חבילת דוחות חדשה. בריצת `both` ייתכן שרק מצב אחד יצליח; סטטוס הריצה והתקציר הטרי מציינים מה הופק. קבצים שנשמרו ממצב אחר או ריצה קודמת אינם הוכחה להצלחה נוכחית.
- אם Yahoo/Investing חסומים בענן או מגבילים קצב, בדקו שלב שנכשל, כיסוי ותאריכי נתונים. בלי מניות מנותחות ההפקה נכשלת; כיסוי חלקי מסומן. חבילת סטטוס/דוחות שמורים נוצרת כשניתן גם בכשל, אך אינה מובטחת אם שלבי ההקמה עצמם נכשלו.
- בכשל ניהול או push בדקו תצורה והרשאות לפני ניסיון חוזר; אין ביטול אוטומטי של commit שכבר הצליח. הפעילו התראות Actions בהגדרות ההתראות האישיות של GitHub ועקבו אחרי דף הריצה. המערכת אינה שולחת דוחות ישירות ל-Gmail.

### Pages אופציונלי

ברירת המחדל אינה מפרסמת אתר. לפרסום מכוון בלבד: **Settings > Pages > Source: GitHub Actions**,
והוספת משתנה Actions בשם `PUBLISH_PAGES` עם הערך המדויק `true`.
**יש להתייחס לאתר Pages כציבורי, גם כשמאגר המקור פרטי**, אלא אם הוגדרה ונבדקה בפועל בקרת גישה
הנתמכת בתוכנית GitHub שלכם. תוכניות מסוימות אינן תומכות ב-Pages ממאגר פרטי; אין להפוך מאגר לציבורי בלי בחינת חשיפת התיק וההיסטוריה.
משתמשים שאינם מעוניינים בפרסום משאירים את המשתנה חסר/`false` ומשתמשים ב-artifact מאומת ממאגר פרטי.

קישורי הניהול נוצרים לפי `GITHUB_REPOSITORY` (מסופק אוטומטית ב-CI) או זיהוי כתובת Pages תקינה.
הם מפנים לטופס Actions המחייב הרשאות, לא לשרת נסתר או לממשק ציבורי לכתיבת התיק.
נכון ל-7.9.2026 אין remote מוגדר בסביבת העבודה המקומית, אך היעד המיועד הוא המאגר `idosharan/stock`
וכתובת Pages המיועדת היא `https://idosharan.github.io/stock/` לאחר העלאה ופרסום;
הרשאות החשבון, הגנת הענף, איסוף נתונים ב-Actions ופריסת Pages בפועל טרם אומתו.

## Google AI אופציונלי

**Google AI Plus הוא מנוי צרכני, לא הבטחה למכסת Gemini API.** הטבות Gemini, Gmail,
אחסון ושירותי מחברות/NotebookLM תלויות בתוכנית, באזור ובחשבון; בדקו את
[הטבות Google AI Plus הרשמיות](https://support.google.com/googleone/answer/16882689).
ניתן להשתמש ידנית בתקציר `.txt` שהורד: לצרפו ב-Gmail, לשמור ב-Drive, לנתח ב-Gemini,
או להעלות ל-NotebookLM אם השירות והתוכנית זמינים. אין כאן חיבור Google אוטומטי,
סנכרון Drive או שליחה ישירה ל-Gmail, ואין צורך להתחבר ל-Google לצורך הדוח הבסיסי.
גם העלאה ידנית מעבירה מידע אישי ל-Google ויש לבחון את תנאי השירות והשיתוף.

להוספת פרשנות Gemini אוטומטית לתקציר, רק לאחר החלטת פרטיות ומכסות:

1. ב-[Google AI Studio](https://aistudio.google.com/) בחרו פרויקט וצרו מפתח Gemini API. אל תמסרו אותו בשיחה. ב-GitHub: **Settings > Secrets and variables > Actions > Secrets > New repository secret**, שם `GEMINI_API_KEY`.
2. באותו מסך, **Variables**, הגדירו `GEMINI_MODEL` לפי מזהה מודל שזמין כעת לפרויקט שלכם ב-AI Studio ותומך ב-`generateContent`. משתמשים במזהה בלבד, ללא `models/`; אין דגם קשיח מובטח, וזמינות/מכסה יכולות להשתנות.
3. רק בהסכמה להעברת **התקציר האישי, לרבות החזקות ומידע כספי שבו, מ-GitHub אל Google חיצוני**, הגדירו `SEND_REPORT_TO_GEMINI=true`. מפתח ומודל ללא opt-in אינם שולחים דבר. לכיבוי השאירו חסר או `false`.
4. בדקו [חיוב ומכסות Gemini API](https://ai.google.dev/gemini-api/docs/billing) ואת [תנאי שימוש בנתונים](https://ai.google.dev/gemini-api/terms). במסלול חינמי תוכן עשוי לשמש לשיפור מוצרים/אימון ולהיבדק בידי אדם; אין לשלוח בו מידע אישי או רגיש. במסלול בתשלום חלים תנאים אחרים, לרבות אי-שימוש באימון כמתואר בתנאים, אך לא הבטחה לאפס שמירה/גישה. מאחר שהתקציר אישי, השאירו את השילוב כבוי אלא אם מסלול החשבון ותנאיו מתאימים לנתונים.

אין כאן הפעלת חיוב, רכישת מכסה או שינוי חשבון מטעמנו. API מחויב ומוגבל בנפרד ממנוי Plus;
בדקו את התעריפים, המכסות וסטטוס הפרויקט בפועל לפני הפעלה. שגיאה, timeout, מפתח/מודל חסרים או
מכסה לא זמינה משאירים את התקציר הדטרמיניסטי כחלופה, ללא תלות בפרשנות AI.
הפרשנות משולבת בראש ה-HTML של אותה הרצה, נשמרת גם כ-`reports/latest-daily-ai.txt`/`reports/latest-weekly-ai.txt` ומסומנת כלא מאומתת;
היא אינה משנה ציונים, מחירים או כללי סיכון. היא עשויה לטעות ואינה מקור נתוני שוק.

## ⚠️ הבהרה

הכלי מבצע ניתוח טכני אוטומטי בלבד ואינו מהווה ייעוץ השקעות.
השקעה בניירות ערך כרוכה בסיכון. התייעץ עם יועץ מורשה לפני קבלת החלטות.
