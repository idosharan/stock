# אייג'נט ניתוח טכני — בורסת ת"א 📈

אייג'נט אוטומטי ב-Node.js/TypeScript שמושך נתוני מניות עדכניים מהאינטרנט בכל הרצה,
מבצע ניתוח טכני (רצועות בולינגר, נרות יפניים, RSI, MACD, ממוצעים נעים),
סורק כתבות בעיתונות הכלכלית הישראלית ומפיק **דוח המלצות יומי/שבועי** של מניות לרכישה.

## מה הוא עושה

- 📊 מושך היסטוריית מסחר (OHLCV) מ-Yahoo Finance עבור מניות ת"א (סיומת `.TA`).
- 🧮 מחשב אינדיקטורים טכניים מרכזיים:
  - **רצועות בולינגר** (Bollinger Bands) + מדד %B
  - **נרות יפניים**: פטיש, כוכב נופל, דוג'י, בליעה שורית/דובית, כוכב בוקר/ערב, שלושה חיילים לבנים / שלושה עורבים שחורים
  - **RSI**, **MACD**, ממוצעים נעים (SMA 20/50)
  - **סטוכסטי**, **Williams %R**, **ADX**, **ATR**, **OBV**
  - **CCI** (Commodity Channel Index), **MFI** (Money Flow Index), **ROC** (מומנטום), **VWAP** מתגלגל
  - נפח מסחר ונזילות (היכן יש "כסף נזיל")
- 📰 גורד כתבות מ-RSS של גלובס / כלכליסט / TheMarker / ynet, ומעריך סנטימנט.
- 🌍 **סקירת מדדי עולם** והמלצות מגמה — ארה"ב (S&P 500, Dow, Nasdaq, Russell, VIX),
  ישראל (ת"א 35 / ת"א 90), אירופה (DAX, FTSE, CAC 40, Euro Stoxx 50)
  ואסיה (Nikkei, Hang Seng, Shanghai, KOSPI).
- 🎯 מדרג כל מניה בציון ‎-100..100 ונותן המלצה: קנייה חזקה / קנייה / החזקה / הימנעות.
- 📄 מפיק דוח HTML בתיקייה `reports/` בכל הרצה.

## התקנה

נדרש Node.js בגרסה 22.13 ומעלה, כולל `node:sqlite`. מומלצת גרסת LTS עדכנית.

```powershell
npm install
```

## הרצה

```powershell
# דוח יומי
npm run daily

# דוח שבועי
npm run weekly
```

הדוחות נשמרים בתיקייה `reports/` בפורמט HTML ונגישים דרך [index.html](index.html).

## חיזוי היסטורי ואימות

המנוע ב-[src/forecast.ts](src/forecast.ts) משווה את המניה למצבי עבר דומים לפי מומנטום,
תנודתיות, מרחק מממוצע ומשיא, נפח וחוזק יחסי מול מדד מתואם לפי תאריך.
המקרים מסוננים לפי מגמה, דשדוש או לחץ. אלה כללים קבועים מראש, לא משקולות שאומנו על תקופת הבדיקה.

- אופקים: 5, 10 ו-20 ימי מסחר; כניסה בפתיחת המסחר הבאה ויציאה בסגירת יום האופק.
- עלות ברירת מחדל: 20 נקודות בסיס לעסקה מלאה, כולל הנחת עמלות והחלקה. אין סימולציית סטופ או תיק השקעות.
- לפחות 12 מקרים לא חופפים בכל אופק, עד 40 שכנים דומים; אחרת אין אומדן הסתברות.
- שכיחות עלייה עם רווח סמך Wilson של 95%, חציון נטו, P10/P90 וקו בסיס בלתי מותנה.
- רווח הסמך הוא בקירוב: תלות בין תקופות מקטינה את המדגם האפקטיבי. P10/P90 מתארים פיזור עבר, לא תחום מובטח לעתיד.
- החיזוי ההיסטורי משתמש רק בימים שהסתיימו ב-UTC. גם לאחר סגירת הבורסה המקומית נר היום ייכלל רק ביום UTC הבא. הניתוח הטכני הרגיל עשוי להיות תוך-יומי.
- נתוני הספק אינם מאגר point-in-time מלא של כל המניות שנמחקו, ואין כאן סדרת תשואה כוללת מאומתת לפעולות הון ודיבידנדים.

```powershell
npm run backtest -- --days=120 --step=5 --limit=20 --cost-bps=20
npm test
npx tsc --noEmit
```

בדיקת התחזיות כרונולוגית, עם תוצאות עבר שהושלמו לפני תאריך ההערכה וללא חפיפה בתוך כל מניה ואופק.
הדוח מציג כיסוי, Brier מול קו בסיס (נמוך עדיף), קבוצות שכיחות צפויה מול בפועל ותשואות נטו.
תצפיות בין מניות עשויות להיות מתואמות. המדגם הוא המניות הראשונות ברשימת המעקב הנוכחית.
פילוח הציונים הטכניים נפרד: `--step=5` עדיין יוצר בו חפיפות באופקים הארוכים.
אין שינוי אוטומטי של משקולות לפי התוצאות ואין טענה שההסתברויות מכוילות.
בבדיקה הראשונית ב-6.9.2026 המודל לא גבר על קו הבסיס ב-Brier, ובאופק 20 ימים לא היה כיסוי מספק.

## אירועים מתוארכים

לא נוצר מאגר חדשות היסטורי מלא מתוך החדשות של היום. בהיעדרו הדוח מציין שרכיב האירועים חסר.
לייבוא רשומות ממקור מאומת יש להשתמש במערך JSON במבנה הבא (דוגמת מבנה בלבד, לא אירוע אמיתי):

```json
[
   {
      "id": "provider-unique-event-id",
      "type": "earnings",
      "symbol": "POLI.TA",
      "occurredAt": "2025-01-01T12:00:00Z",
      "publishedAt": "2025-01-01T12:05:00Z",
      "source": "https://example.com/original-release"
   }
]
```

```powershell
npm run events:import -- path/to/verified-events.json
```

הייבוא אטומי ושומר מזהים ייחודיים; מזהה עם תוכן שונה גורם לשגיאה במקום לשכתב היסטוריה.
יש לכלול שעה ואזור זמן. אירוע שפורסם לאחר מועד החיזוי לא משתתף במחקר.
הדוח מציג מחקר אירועים נפרד של 10 ימי מסחר מהפתיחה הראשונה לאחר פרסום/התרחשות,
עם דילול אירועים חופפים וסף 12 מקרים. הוא אינו מוכיח סיבתיות ואינו משנה את תחזית השכנים.
אין כרגע נתוני ציפיות/הפתעות מאקרו או אימות מחוץ למדגם של רכיב האירועים.

## אחסון ומגבלת קבצים

```powershell
npm run storage:maintain
```

- המטמון מאוחד ב-[.cache/candles.sqlite](.cache/candles.sqlite); ההיסטוריות והאירועים ב-[reports/state.sqlite](reports/state.sqlite).
- ההעברה מה-JSON הישן בודקת תקינות וקריאה חוזרת לפני מחיקת כל מקור בנפרד. קובץ פגום או סותר נשמר ומדווח.
- נשמרים עד 30 דוחות HTML מתוארכים פעילים. ישנים יותר נשמרים כ-Base64 במסד ההיסטוריה תחת `html:<filename>` לפני הסרתם מהתיקייה.
- הארכיון אינו מוצג באתר הסטטי; הוא נשמר לגיבוי/שחזור. עמוד האינדקס אינו מקשר לקבצים שהועברו לארכיון.
- פקודת התחזוקה נכשלת אם מספר הקבצים עולה על 100 או אם ההעברה נכשלה. הספירה אינה כוללת `.git`, `node_modules` ו-`node_modules - Copy`.
- התלויות ושכפולן לא נמחקו. לכן זו אינה תקרה של 100 קבצים פיזיים בכל סביבת Node המקומית.
- יש לגבות את מסד ההיסטוריה. GitHub Actions שומר אותו במאגר אך מפרסם ב-Pages רק HTML; SQLite הוא קובץ בינארי שאין למזג ידנית בין ענפים.

## תצוגה ובדיקות

הדוחות כוללים טבלת דירוג ניתנת לחיפוש ומיון, גלילה בתוך טבלאות רחבות, ניווט מקלדת,
תצוגת הדפסה ומקטעי ראיות מתקפלים. `npm run summary -- --top=5` קורא את טבלת הדירוג
ולא את טבלת ההחזקות; הסדר הוא הציון המשולב, ולא בהכרח הציון היומי.

## ☁️ הרצה ופרסום ב-GitHub (Actions + Pages)

### העלאה דרך הדפדפן: פחות מ-100 קבצים

אין לגרור את כל תיקיית העבודה לאתר GitHub: העלאה בדפדפן אינה מסננת לפי `.gitignore`,
ולכן גם אלפי קובצי התלויות עלולים להיכלל.

```powershell
npm run upload:prepare
```

הפקודה יוצרת תיקיית `github-upload` חדשה בלבד, מאמתת עד 100 קבצים ועד 25MB לקובץ,
ומעתיקה את קובצי המקור, הבדיקות, הכלים, הדוחות, מסד ההיסטוריה והגדרות GitHub Actions.
היא אינה כוללת תלויות, מטמון, תיקיית Git, הגדרות VS Code או קובצי סודות.
מסד ההיסטוריה מועתק כתמונת SQLite עקבית ונבדק לפני אישור ההכנה.
אם התיקייה כבר קיימת, הפקודה עוצרת בלי לדרוס אותה; יש להעביר אותה למיקום אחר לפני הכנה חוזרת.

במאגר החדש ב-GitHub בחר **Add file → Upload files** וגרור את **התוכן מתוך** תיקיית
`github-upload`, לא את התיקייה העוטפת. יש לכלול גם את `.github`, `.gitignore` ו-`.gitattributes`.
בסיום `package.json` צריך להופיע בשורש המאגר, ולא בתוך תיקיית `github-upload`.
GitHub Actions מתקין את התלויות באמצעות `npm ci`; אין להעלות `node_modules`.
החבילה כוללת נתוני תיק ומחירי קנייה: מומלץ מאגר פרטי; הפעלת Pages אינה מבטיחה אתר פרטי.

ניתן לארח את הפרויקט ב-GitHub ולהריץ אותו בענן — ללא מחשב מקומי. הקובץ
[.github/workflows/reports.yml](.github/workflows/reports.yml) מגדיר זאת:

1. **העלאת הפרויקט ל-GitHub:**
   ```powershell
   git init
   git add .
   git commit -m "initial commit"
   git branch -M main
   git remote add origin https://github.com/<USER>/<REPO>.git
   git push -u origin main
   ```
2. **הפעלת GitHub Pages:** Settings → Pages → Source: **GitHub Actions**.
3. **הרצה אוטומטית (cron):** דוח יומי בימים א'-ה' ב-16:00 UTC (אחרי נעילת ת"א) ודוח שבועי
   ביום חמישי ב-16:30 UTC — מופקים אוטומטית, נשמרים ב-`reports/` ומתפרסמים ל-Pages.
   הרצה לפני נעילת המסחר מחזירה את נתוני היום הקודם ומייצרת דוח כפול.
4. **הרצה ידנית:** לשונית **Actions** → "Build & Deploy Reports" → **Run workflow**
   (בחירת יומי / שבועי / שניהם).
5. **הון התיק (אופציונלי):** Settings → Secrets and variables → Actions → Variables →
   `PORTFOLIO_CAPITAL` (ברירת מחדל 100,000 ₪) — משמש לחישוב גודל הפוזיציה בהמלצות.

הדוחות יוצגו בכתובת `https://<USER>.github.io/<REPO>/`.
כפתורי ההרצה בדף מזהים אוטומטית סביבת Pages ומפנים ללשונית Actions
(שם מתבצעת ההרצה בענן), שכן Pages מגיש קבצים סטטיים בלבד.

> הערה: הרצה אינטראקטיבית בלחיצה ישירה (`/api/run`) פעילה רק במצב מקומי `npm run web`.
> ב-GitHub ההרצה מתבצעת דרך Actions (בענן), והתוצאה מתפרסמת חזרה ל-Pages.
